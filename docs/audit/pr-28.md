## 3. Manual review of the diff

- No ROM routine address, no offset inside the ROM, no instruction listing in comments or docs, no new data table.
- Provenance stated in the PR description: the contract was read from Deluxe Paint III's own overlay manager and file
  layout (a third-party program) and the public hunk format; the Kickstart ROM and AROS were not used.
- The PR description mentions a `.gitignore` change (`adf/`, `.DS_Store`) that is not part of the PR's commits.
- Technical points left open (not blocking):
  - `LoadSeg` with D1 = 0 and non-zero D2/D3 is now taken as an overlay node load; a caller leaving junk in D2/D3
    would make LoadSeg read a random "table". Whether 1.3 behaves the same is unproven (needs a black-box probe).
  - The +20 field of the overlay header (global vector) is left untouched; AROS fills it and uses it to recognise an
    overlay root in UnLoadSeg. Our UnLoadSeg checks the marker and `table[0]` = seglist instead.
  - UnLoadSeg of an overlay root closes the file and frees both tables but not the node still loaded (AROS does the
    same); it calls Close, so it must run in a process (true for the shell and Workbench callers).
