| test | screen | window |
|---|---|---|
| H, 100 horizontal Draws | 5.2 → **11.0** (slower) | 7.0 → **8.4** (slower) |
| V, 100 vertical Draws | 25.5 → 4.7 | 24.4 → 20.0 |
| D, 50 diagonal Draws | 215.0 → 5.5 | 174.0 → 175.5 |
| R, 10 solid RectFills | 19.6 → 9.4 | 14.3 → 8.2 |
| P, patterned RectFill | 7.5 → 7.5 | 6.1 → 6.2 |
| X1-X4 Text, B BltTemplate | unchanged (±1 frame) | unchanged |

Points to settle:

1. **Horizontal lines are about twice slower** without a layer (and 20 % slower in a window): the line-mode blit
   replaced a faster CPU row fill for the most common case (borders, frames).
2. **Asynchronous Draw and memory release**: Draw now returns while the blitter still writes its last plane. CPU
   consumers wait first, but the release paths do not: `FreeRaster` (`text.s`) and the screen plane release in
   `sc_free` (`screens.s`) free memory that a pending line blit may still write. A `WaitBlit` there (and before any
   other release of drawable memory) would close it.
3. `.dd_permit` in `gfx_Draw` releases the blitter semaphore by writing its fields directly with raw offsets
   (`14(a3)`, `44(a3)`); named fields or ReleaseSemaphore would be safer.
4. The PLAN entry is placed above "Context" instead of with the other dated entries, and still lists
   "rp minterms[] not computed", closed by rank 10.
5. The `make test*` targets need Copperline, which the project's harness does not use; fine as optional targets,
   but the PR validation here relied on our own probes.
