# Clean-room audit of PR #42 (Intuition: keep the application's RastPort state across frame redraws) — 2026-11-13

Head `e5e5ca1` ("Intuition: keep the application's RastPort state across frame redraws"), base `716f385`
(`git merge-base`, current `main`). `wn_titlebar_nc`, `wn_veil` and `wn_sysgads_nc` now save the frame RastPort's
drawing state into a 20-byte stack buffer before drawing and restore it afterwards, through two new helpers
`wn_rpkeep`/`wn_rpback` that call the existing `it_rpsave`/`it_rprest`. Outside GIMMEZEROZERO the frame RastPort is
the application's own, and a RefreshGList over the system gadgets used to leave it in JAM1 with the pictogram pen
(KindWords drew its page over the old picture after a scroll). A new analysis page
`docs/analysis/kindwords-scroll-v34.md` records the KindWords page-down call trace on the real Kickstart 1.3.

`docs/analysis/kindwords-scroll-v34.md` (new, 310 lines). Audit gate of `CLAUDE.md` ("Pull requests").

**Clean-room verdict: PASS.** No match with the original ROM reaches the notable threshold, the PR adds no code
match above the base's longest (13 instructions / 19 words), the AROS figures stay within the base's maxima, and
the new analysis page contains no transcribed code and no Commodore ROM address.

## 3. Manual review of the diff

- `src/intuition/screens.s`: the stack buffer set-up/release around the three frame routines and two four-
  instruction helpers built on the existing `wn_brp`/`it_rpsave`/`it_rprest`. Comments explain the reason
  (KindWords, RefreshGList over the system gadgets) and cite no ROM address. No instruction listing, no data table.
- `docs/ARCHITECTURE.md`, `docs/PLAN.md`: implementation-side description of the change and of the trace ROM
  experiment on **our** ROM. No ROM address.
- Public-repo check (`.claude/rules/public-repo.md`) on the whole PR diff: no hit.
- **`docs/analysis/kindwords-scroll-v34.md` (new):** black-box observation of the real Kickstart 1.3 under
  vAmigaWeb, with RetroShell breakpoints at library LVO entry points and reads of public structure fields while
  paused. It describes behaviour and ABI only: the sequence of graphics/layers calls KindWords makes during a
  page-down, their arguments and the RastPort state (JAM2, pens 0/1, no SetDrMd during the redraw), the TextFont
  fields of the fonts on the TextFonts list, and the layer/ClipRect state. No instruction listing, no pseudo-code
  transcription, no Commodore ROM address or offset, no ROM data (no glyph or CharLoc data; only the public
  `TextFont` header fields of the ROM topaz fonts).
  - Every hex value in the page is either a public structure field offset (`Layer+$1E` Flags, `RastPort+$18`
    Mask, `RastPort+$1C` DrawMode, `GfxBase+$8C` TextFonts, `GfxBase+$9A` DefaultFont, all checked against the
    NDK layout), a flag or style value, a character range, or a bitplane byte value. The LVO numbers quoted
    (graphics: Text, SetFont, RectFill, BltTemplate, BltClear, SetRast, ScrollRaster, ClipBlit, ClearEOL,
    ClearScreen, RemFont; layers: ScrollLayer, BeginUpdate, EndUpdate) match the public `.fd`.
  - No address inside KindWords appears; the only addresses mentioned are described in words (fonts in slow RAM).
  - For human review (not a clean-room violation): §3 and §4.3/§7 state that `Text` reaches `BltTemplate` (and, per
    §3, `BltClear`) through the library vector. That is an observation of the ROM's internal call structure, made
    at the LVO entry points, not of its code; it is observable by any program that patches those vectors with
    `SetFunction` (as FastFonts does), so it stays within behaviour/ABI.
  - Remarks: the screenshot paths (`build/vamigaweb/analysis/…`) are not in the repository; the disks are named by
    title only.
