# Clean-room audit of PR #41 (Workbench busy pointer while icons open) — 2026-11-13

Outside contribution, head `dd560b4` ("Workbench: busy pointer while icons open, as on 1.3"), base `5ebfb79`
(`git merge-base`, current `main`). `wb_openall` now raises the busy pointer before opening the selected icons and
drops it when they are all open; `wb_opendrawer` gives the busy pointer to a Workbench window opened while busy mode
is on. A new section §11 of `docs/analysis/workbench-task-v34.md` describes when the 1.3 Workbench shows the busy
pointer.

## 3. Manual review of the diff

- `src/dos/workbench.s`: two calls to the existing `wb_busy` in `wb_openall` and a guarded call in
  `wb_opendrawer`, with comments citing the spec. No ROM address, no instruction listing, no data table.
- Public-repo check (`.claude/rules/public-repo.md`) on the whole PR diff: no hit.
- **§11 of `docs/analysis/workbench-task-v34.md` (new):** black-box observations of the real Kickstart 1.3 under
  vAmigaWeb (screenshot sequences at 200 ms intervals). It describes behaviour only: when the busy pointer appears
  and disappears for a drawer/disk double-click and a tool launch, and on which windows it shows. No instruction
  listing, no pseudo-code transcription, no Commodore ROM address or offset, no ROM data; the pointer image itself
  is explicitly not described. Inferred points are tagged **[D]** and rest on the public `SetPointer`/`OpenWindow`
  contract. The disk is named by its local alias, the only URL is the public vAmigaWeb site. Two remarks, not
  clean-room issues: the `[shot: …]` tags name screenshot files that are not in the repository, and "heap
  screenshots" is unclear wording (probably the emulator's frame buffer).
