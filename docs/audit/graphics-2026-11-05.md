# Graphics and memory clean-room audit — 2026-11-05

## Result and scope

**PASS for the audited binary delta under the fixed historical gate, with a
control-corpus limitation.** No new unclassified code match exceeds the
base's qualified code peak of 19 words / 13 instructions, and no unqualified
code match reaches the fixed 40-word / 19-instruction gate. Both positive controls found
12 of 12 planted fragments. The paired AROS source comparison found no new
exact passage of 20 or more tokens.

The historical unrelated executable corpus was unavailable on this machine.
Its threshold was retained explicitly, not recalibrated or described as
reproduced. Available Workbench and AROS binary controls were measured under
different names, identically for base and candidate. The pinned AROS source
corpus, in contrast, was reproduced with the documented counts.

This is a similarity audit, not proof of derivation history. Deliberate
black-box analysis of the original ROM did occur in a sealed analysis agent.
Observable behavior and public API facts crossed into implementation through
the sanitized Clock report. That permitted workflow must be distinguished
from copying ROM implementation code. The measurements cannot detect every
semantic paraphrase or establish that no reverse engineering occurred.

## Provenance and review limitations

The implementation author reports using the project's own CPU fallback,
public Hardware Reference Manual chapter 6, public ABI/AutoDoc/header facts,
and the sanitized Clock behavior report. This is an attributed provenance
statement, not a conclusion inferred from similarity scores. The
implementation track separately reports its source provenance scan and
architecture review passed. Functional regressions and performance checks
are recorded by that track and are not substitutes for this audit.

The analysis agent kept original-ROM execution, checkpoint inspection, and
reference access in its separate context. The implementation track received
behavioral reports, not raw original logs, screenshots, memory dumps, or
disassembly. The Clock report now has a dated clean-room review.

Limitations remain: the historical binary control corpora were not rerun;
only Kickstart revision 34.5 was compared; linear instruction decoding also
passes through data; the AROS source audit covers the seven changed files
rather than all project source; and lexical/binary comparisons cannot rule
out arbitrary semantic paraphrases, translated algorithms, prior model
memorization, or undocumented historical inputs. The positive control
demonstrates sensitivity to planted relocated binary fragments, not to all
possible forms of derivation.

This report was reviewed to contain only aggregate reference statistics,
implementation-side symbols and offsets, public facts, and findings. It
contains no original-ROM code, bytes, routine addresses, or reference-side
offsets. No visible emulator session was disturbed.
